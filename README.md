# 🐉 Gold Dragon Trading Bot

بوت تداول آلي لزوج **XAU/USD** فقط، مبني على بروتوكول
**Gold Dragon Algorithm Pro v4** (Smart Money Concepts + هندسة السيولة).

هذا المستودع يحتوي على **الأدلة النظرية** (في `docs/`) و**الكود التنفيذي
الكامل** الذي يطبّقها (في `src/`).

---

## ⚠️ تنويه إلزامي — اقرأه قبل أي شيء

> هذا المشروع **تعليمي/تقني**. لا يشكّل توصية مالية أو استثمارية، ولا يضمن
> أي نتيجة. التداول الآلي على الذهب ينطوي على احتمال حقيقي لفقدان رأس المال
> **بالكامل**، وبسرعة أكبر من التداول اليدوي.
>
> 1. لا تشغّله على حساب حقيقي قبل **3 أشهر** متواصلة على حساب تجريبي.
> 2. اختبر Kill Switch يدوياً وتأكد أنه يغلق المراكز فعلاً.
> 3. لا تستخدم مالاً تحتاجه (إيجار، ديون، مصاريف معيشة).
> 4. راجع شروط وسيطك: بعض الوسطاء يمنعون البوتات.
> 5. التزم بقوانين الضرائب والتنظيم في بلد إقامتك.
>
> **المسؤولية الكاملة على المستخدم وحده.**

بخصوص خطة `docs/Gold_Dragon_Challenge_Plan.md` تحديداً: تحويل 100$ إلى 1000$
خلال 8–12 أسبوعاً يتطلب نمواً مركباً ~15% أسبوعياً، وهو معدل لا تحققه صناديق
محترفة على المدى الطويل. الوثيقة نفسها تُقدّر احتمال الوصول بـ 30–40٪ واحتمال
الإفلاس بـ 10–20٪، والتقدير الأول متفائل بكثير. الكود هنا يفرض حدود المخاطرة
بحزم، لكنه **لا يستطيع** جعل هذه الخطة واقعية. وضع التحدي معطّل افتراضياً.

## ⚡ التشغيل السريع

```bash
git clone <repo> && cd Gold_Dragon_Trading_Bot_Guide
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt

python -m src.main doctor        # فحص الإعدادات والبيئة
python -m src.main analyze       # تحليل واحد + تقرير كامل
python -m src.main run --once    # دورة واحدة (تجريبية)
```

الوضع الافتراضي **آمن**: `dry_run: true` + بيانات اصطناعية + وسيط ورقي.
لا يُرسل أي أمر حقيقي ولا يحتاج حساباً لدى وسيط.

## ⚙️ الإعدادات

كل شيء في `config/*.yaml`. أي مفتاح يُتجاوَز من البيئة:

```bash
export GD_BOT__DRY_RUN=false
export GD_RISK__RISK_PER_TRADE=0.005
```

**الأسرار لا تُكتب في YAML إطلاقاً** — انسخ `.env.example` إلى `.env`:

| المتغير | الغرض |
|---|---|
| `GD_MT5_LOGIN` / `GD_MT5_PASSWORD` / `GD_MT5_SERVER` | حساب MetaTrader 5 |
| `GD_TELEGRAM_TOKEN` / `GD_TELEGRAM_CHAT_ID` | إشعارات Telegram |

### أهم القيم

| المفتاح | الافتراضي | المعنى |
|---|---|---|
| `bot.dry_run` | `true` | لا أوامر حقيقية |
| `bot.feed` | `synthetic` | `mt5` \| `csv` \| `synthetic` |
| `gold_dragon.min_acs` | `7.0` | حد قبول الإشارة (من 10) |
| `risk.risk_per_trade` | `0.01` | 1% لكل صفقة |
| `risk.max_risk_per_trade` | `0.02` | سقف مطلق — الإعداد يرفض ما فوقه |
| `risk.min_rr.with_trend` | `3.0` | يُقاس على TP2 |
| `kill_switch.drawdown_terminate` | `0.50` | إيقاف نهائي بتدخل بشري |

## 🧪 الاختبار

```bash
pip install -r requirements-dev.txt
pytest -q          # 143 اختباراً
ruff check src tests scripts
```

الاختبارات تغطي: حساب حجم المركز، الأقفال وبقاءها بعد إعادة التشغيل، محاكاة
الوسيط (SL/TP داخل الشمعة)، كل بوابة على حدة، ومسار كامل من البيانات إلى
الصفقة المُدارة.

### Backtest

```bash
python scripts/make_sample_data.py --bars 5000   # بيانات اصطناعية
# أو صدّر بيانات حقيقية من MT5 إلى data/XAUUSD_M15.csv بالأعمدة:
# time,open,high,low,close,volume
python -m src.main backtest --bars 5000 --balance 1000
```

قيود الـ Backtest مكتوبة في رأس `src/backtest.py` — اقرأها قبل تصديق أي رقم.
أهمها: التنفيذ عند إغلاق شمعة M15، وافتراض ضرب SL أولاً عند ملامسة SL و TP
في الشمعة نفسها.

## 🚂 النشر السحابي (Railway) — اختبار أمامي

```bash
GD_BOT__FEED=yahoo GD_BOT__DRY_RUN=true python -m src.main run
```

على Railway يعمل البوت في وضع **Forward Test**: بيانات XAU/USD حقيقية عبر
HTTP + تحليل كامل + تنفيذ ورقي + إشعارات Telegram + صفحة مراقبة على `/`.

**MetaTrader5 لا تعمل على Linux**، لذا لا اتصال بحساب MT5 من Railway. الكود
يرفض الإقلاع إذا حاولت الجمع بين `dry_run: false` ومصدر بيانات غير MT5.

الدليل الكامل (القرص الدائم، المتغيرات، التحقق، التكلفة، حل المشاكل):
[`docs/DEPLOY_RAILWAY.md`](docs/DEPLOY_RAILWAY.md)

| مصدر البيانات | المفتاح | الملاحظة |
|---|---|---|
| `yahoo` | لا يحتاج | XAUUSD=X + DXY/US10Y/VIX/SPX للارتباط |
| `twelvedata` | `GD_TWELVEDATA_KEY` | أدق، ~800 طلب/يوم مجاناً |
| `metaapi` | `GD_METAAPI_TOKEN` + `GD_METAAPI_ACCOUNT_ID` | حساب MT5 حقيقي/تجريبي من أي نظام |
| `mt5` | — | Windows فقط، للتنفيذ الحقيقي |
| `csv` / `synthetic` | — | للاختبار والـ Backtest |

## 🖥️ التشغيل الحقيقي

MetaTrader5 Python API تعمل على **Windows فقط** وتحتاج طرفية MT5 مفتوحة على
نفس الجهاز. الحاوية (Docker) تصلح للتحليل والـ Backtest والوضع التجريبي، لا
للتداول الحقيقي.

```bash
# على خادم Windows بجوار طرفية MT5:
pip install MetaTrader5
# فعّل في الطرفية: Allow Automated Trading
```

ثم في `config/settings.yaml`: `dry_run: false` و `feed: mt5`، وأخيراً:

```bash
python -m src.main run --live      # يطلب كتابة LIVE للتأكيد
```

### أوامر التشغيل اليومي

```bash
python -m src.main metaapi               # فحص اتصال MetaApi قبل التشغيل
python -m src.main psych --state calm    # إعلان الحالة النفسية (تنتهي بعد 12 ساعة)
python -m src.main report                # الأداء + الذاكرة التكيفية
python -m src.main kill --reset          # فكّ Kill Switch يدوياً
tail -f logs/bot.log
```

## 🔧 أين خالف الكود نصّ الدليل ولماذا

الأدلة في `docs/` هي المرجع النظري، ومقاطع الكود فيها توضيحية. عند البناء
التنفيذي ظهرت مواضع لا تصلح كما هي:

| الموضع | ما في الدليل | ما في الكود | السبب |
|---|---|---|---|
| حجم المركز | تحويل المسافة إلى «بِبس» ثم ضرب في 100 | `lots = المخاطرة ÷ (مسافة الوقف × 100)` | صيغة الدليل تُضخّم الحجم ~×100 وتُصفّي الحساب في صفقة واحدة |
| القفل بعد 3 خسارات | `threading.Timer` | حالة على القرص بختم زمني | مؤقّت الذاكرة يزول بإعادة التشغيل، فيسقط القفل |
| مقياس ACS | «0–10» بينما المصفوفة مجموعها 14 | حساب خام /14 ثم تطبيع إلى /10 | إزالة تناقض عددي مع بقاء التفصيل البنَدي |
| الدخول | من حافة POI | بسعر السوق عند التريغر + رفض إن ابتعد السعر > 1R عن الحافة | البوت يرسل أوامر سوقية؛ خطة مبنية على سعر لن يُنفَّذ تجعل RR والحجم وهميين |
| كشف السويپ | اختراق المستوى | **ظل** يخترق و**إغلاق** يعود خلفه | الإغلاق خارج المستوى كسر هيكلي لا سويپ — والخلط بينهما أغلى خطأ في تطبيقات SMC |
| إشعارات Telegram | `asyncio.run` داخل دالة متزامنة | `requests` متزامن | ينهار عند وجود حلقة أحداث، وينشئ حلقة لكل رسالة |
| فلتر الأخبار | `return False` ثابت | تقويم JSON محلي + حالة «غير معروف» عند غيابه | «لا أخبار» افتراضاً أمان زائف |
| الحالة النفسية | +1 ثابتة | إقرار بشري من الطرفية ينتهي بعد 12 ساعة | البوت لا يعرف مزاجك؛ الصمت ليس موافقة |
| TP2 | 2R مع حد أدنى RR 1:3 | 3R (وTP3 عند 5R) | الإعدادان متناقضان: كل صفقة كانت سترفَض |
| الإغلاق الجزئي | مفترض دائماً | يُتخطّى صراحةً إن كان الجزء < أصغر لوت | 30% من 0.01 لوت غير قابلة للتنفيذ لدى أي وسيط |

كما أُضيفت وحدات لا وجود لها في الدليل: طبقة وسيط مجردة (تجعل الاختبار
والـ Backtest ممكنين دون MT5)، مزامنة المراكز مع الوسيط (وإلا بقي البوت يحسب
مخاطرة صفقات مُغلقة)، وتحقق من السبريد والانزلاق قبل الإرسال.
