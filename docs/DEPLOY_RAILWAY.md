# 🚂 النشر على Railway وبدء الاختبار الأمامي (Forward Test)

دليل خطوة بخطوة لتشغيل Gold Dragon Bot على Railway ومتابعة نتائجه.

---

## ⚠️ اقرأ هذا أولاً — ما الذي يعمل فعلاً على Railway

| السؤال | الجواب |
|---|---|
| هل سيتصل البوت بحساب MT5 تجريبي؟ | **لا.** مكتبة MetaTrader5 ويندوزية وتتطلب طرفية MT5 مفتوحة على نفس الجهاز. Railway حاويات Linux. |
| إذن ماذا سيفعل؟ | **Forward Test:** بيانات سوق **حقيقية** لحظية + تحليل كامل + تنفيذ **ورقي** داخلي، مع إشعارات Telegram لكل إشارة. |
| هل النتائج ذات قيمة؟ | نعم كمؤشر على جودة المنطق وتكرار الإشارات. ولا، كبديل عن حساب تجريبي لدى وسيطك: السبريد والانزلاق والتنفيذ ستختلف. |
| كيف أحصل على حساب MT5 تجريبي حقيقي؟ | عبر **MetaApi.cloud** — محوّله جاهز في الكود ويعمل من Railway نفسه (القسم 9). أو VPS ويندوز. |

الكود يمنعك من الخلط: `dry_run=false` يتطلب أن يكون مصدر البيانات ومنفّذ الأوامر من نفس الوسيط (`mt5` أو `metaapi`) — تنفيذ أوامر حقيقية بأسعار مزوّد خارجي خطأ لا يُغتفر.

**مسار مقترح:** انشر الاختبار الأمامي اليوم (أقسام 1–8)، وحين يستقر شغّل `metaapi --check` وانتقل إلى حساب تجريبي حقيقي على نفس الخدمة (القسم 9-ب) دون تغيير أي سطر في المنطق.

## 1) المتطلبات

- حساب [Railway](https://railway.app) (الخطة المجانية تكفي للبداية — راجع قسم التكلفة).
- المستودع على GitHub (جاهز).
- بوت Telegram للإشعارات (اختياري لكن موصى به بشدة).

### إنشاء بوت Telegram في دقيقتين
1. افتح [@BotFather](https://t.me/BotFather) → `/newbot` → اتبع الخطوات → انسخ الـ **Token**.
2. أرسل أي رسالة لبوتك الجديد.
3. افتح [@userinfobot](https://t.me/userinfobot) → أرسل `/start` → انسخ الـ **Id** (هذا هو `chat_id`).

## 2) إنشاء الخدمة

1. من لوحة Railway: **New Project → Deploy from GitHub repo**.
2. اختر `Gold_Dragon_Trading_Bot_Guide`.
3. Railway سيكتشف `railway.json` و`Dockerfile` تلقائياً ويبدأ البناء.

> إن كان الفرع الافتراضي في GitHub ما زال `claude/trading-bot-guide-4yuo9x`، اختره في **Settings → Source → Branch**، أو غيّر الافتراضي إلى `main` أولاً.

## 3) القرص الدائم (خطوة إلزامية — لا تتخطاها)

نظام ملفات الحاوية على Railway **مؤقت**: كل إعادة نشر يمسح كل شيء. بدون قرص دائم:

- قاعدة الصفقات تُمسح → لا سجل أداء ولا ذاكرة تكيفية.
- **قفل الـ 48 ساعة بعد ثلاث خسارات يُلغى مع كل إعادة نشر** — وهو بالضبط العطل الذي أُصلح في الكود، فلا تُعِده من باب الاستضافة.

**الخطوات:** من الخدمة → **Variables ← بجوارها زر `+ New` → Volume** → Mount path:

```
/data
```

## 4) المتغيرات

من الخدمة → **Variables → Raw Editor** → الصق التالي (وعدّل قيم Telegram):

```bash
GD_BOT__DRY_RUN=true
GD_BOT__FEED=yahoo
GD_BOT__LIVE_SYMBOL=XAUUSD=X

GD_STORAGE__DATABASE=/data/trades.db
GD_STORAGE__LOG_FILE=/data/bot.log
GD_KILL_SWITCH__STATE_FILE=/data/kill_switch.json
GD_GOLD_DRAGON__PSYCHOLOGY_GATE__STATE_FILE=/data/psychology.json
GD_NEWS__CALENDAR_FILE=/data/news_calendar.json

GD_BOT__SCAN_INTERVAL_SECONDS=300
GD_BOT__POSITION_CHECK_SECONDS=300

GD_BROKER__PAPER_BALANCE=1000
GD_BROKER__PAPER_SPREAD=0.30

GD_NOTIFICATIONS__PROVIDER=telegram
GD_TELEGRAM_TOKEN=ضع_التوكن_هنا
GD_TELEGRAM_CHAT_ID=ضع_المعرف_هنا
```

القائمة الكاملة مع الشروح في `.env.railway.example`.

> **لماذا 300 ثانية؟** مزوّد البيانات المجاني له حصة. فحص كل 5 دقائق كافٍ لإطار M15 (الشمعة تُغلق كل 15 دقيقة) ولا يستنزف الحصة.

## 5) التحقق من نجاح النشر

بعد اكتمال البناء:

**أ) السجلات** (Deployments → View Logs) — يجب أن ترى:
```
PaperBroker جاهز — رصيد افتتاحي 1000.00
نقطة الفحص الصحي تعمل على 0.0.0.0:XXXX
نتيجة الدورة: no_signal — ...
```

**ب) Telegram** — تصلك رسالة:
```
🐉 Gold Dragon Bot بدأ التشغيل
الوضع: 🧪 تجريبي (dry-run)
```

**ج) صفحة المراقبة** — Settings → Networking → **Generate Domain**، ثم افتح الرابط:
- `/` صفحة حالة عربية (الرصيد، السعر، ACS، آخر دورة، Drawdown)
- `/status` نفس البيانات JSON
- `/health` فحص Railway الآلي

> الرابط عام لمن يعرفه. لا يكشف أسراراً، لكنه يكشف حالة حسابك التجريبي — أبقه لنفسك، أو احذف الـ Domain واكتفِ بالسجلات.

## 6) ماذا تتوقع في الأيام الأولى

**البوت سيرفض معظم الوقت — وهذا هو المطلوب.** الشروط مجتمعة (سويپ مؤكد + CHoCH + POI معتمدة + داخل Killzone + ACS ≥ 7 + ارتباط غير متعارض) نادرة عمداً.

| المدة | المتوقع واقعياً |
|---|---|
| أول 24 ساعة | 0–1 إشارة. غالباً لا شيء. |
| أول أسبوع | 1–4 إشارات. |
| أول شهر | 5–15 إشارة. |

راقب الأسباب في السجلات: `no_signal — لا يوجد اتجاه صالح` تعني ببساطة أنه لم يحدث سويپ مؤكد.

### إن أردت رؤية إشارات أكثر أثناء التجربة

```bash
GD_GOLD_DRAGON__MIN_ACS=6.5          # بدل 7.0
GD_GOLD_DRAGON__KILLZONE_ONLY=false  # تحليل على مدار الساعة
```

⚠️ هذا للاستكشاف فقط. تخفيف الشروط يرفع عدد الصفقات ويخفض جودتها — وهو أسرع طريق لخسارة حقيقية لاحقاً. أعدها لقيمها قبل أي تقييم جدي.

## 7) المتابعة الدورية

```bash
# محلياً بعد سحب قاعدة البيانات، أو عبر Railway CLI:
railway run python -m src.main report
```

يعرض: عدد الصفقات، نسبة النجاح، Profit Factor، متوسط R، وأداء كل نوع POI.

**معايير الحكم بعد 3 أشهر** (من الدليل، البند 8.2):

| المؤشر | الحد الأدنى للقبول |
|---|---|
| نسبة النجاح | ≥ 45% |
| Profit Factor | ≥ 1.2 |
| Max Drawdown | ≤ 15% |
| متوسط RR | ≥ 1:2.5 |

دون ذلك: لا تنتقل إلى حساب حقيقي. عدّل البروتوكول أو أوقفه.

## 9) حساب MT5 تجريبي حقيقي — الخياران

### الخيار أ: VPS ويندوز (الأقرب للواقع)
1. VPS ويندوز (Contabo / Vultr / ForexVPS) ~10–20$/شهر.
2. ثبّت طرفية MT5 وسجّل الدخول بحساب تجريبي من وسيطك.
3. فعّل **Allow Automated Trading** في إعدادات الطرفية.
4. ```powershell
   git clone <repo> && cd Gold_Dragon_Trading_Bot_Guide
   pip install -r requirements.txt
   pip install MetaTrader5
   ```
5. في `config/settings.yaml`: `feed: mt5` و`dry_run: false`، وضع بيانات الحساب في `.env`.
6. `python -m src.main doctor` ثم `python -m src.main run --live`.

**هذا هو المسار الذي تُقاس عليه الأشهر الثلاثة قبل أي حساب حقيقي.**

### الخيار ب: MetaApi.cloud (يعمل من Railway) — **مُنفَّذ في الكود**

`src/infra/metaapi.py` يحتوي محوّلاً كاملاً: تنفيذ الأوامر، المراكز، الإغلاق الجزئي، تعديل الوقف، الأرباح المحققة من سجل الصفقات، والشموع التاريخية من نفس الحساب.

#### 1) إعداد الحساب لدى MetaApi
1. سجّل في [app.metaapi.cloud](https://app.metaapi.cloud).
2. **Add account** → اختر MT5 → أدخل بيانات حسابك **التجريبي** (رقم الحساب، كلمة المرور، اسم السيرفر).
3. اختر **Region** وسجّلها (مثلاً `new-york`).
4. انتظر حتى تصبح الحالة **DEPLOYED** و**CONNECTED**.
5. من **Tokens** أنشئ توكناً وانسخه.

#### 2) الفحص الإلزامي قبل التشغيل

```bash
export GD_METAAPI_TOKEN=...
export GD_METAAPI_ACCOUNT_ID=...
python -m src.main metaapi
```

يفحص: حالة النشر، بيانات الحساب، **مواصفات الرمز** (حجم العقد وأصغر لوت — الأرقام التي يُبنى عليها حجم المركز)، السعر اللحظي، الشموع التاريخية، والمراكز. ويطبع ما تلقّاه فعلاً.

> ⚠️ **مهم**: كُتب هذا المحوّل من توثيق MetaApi ولم يُختبر مقابل الخدمة الحية (بيئة البناء بلا وصول شبكي إليها). أمر `metaapi` هو أداة التحقق. إن فشل فحص، أرسل لي مخرجاته وأصلح الفرق فوراً — لا تُشغّل قبل أن تنجح كل الفحوص.

#### 3) التفعيل

```bash
GD_BOT__DRY_RUN=false
GD_BOT__FEED=metaapi
GD_BROKER__PROVIDER=metaapi
GD_BROKER__METAAPI_REGION=new-york
GD_METAAPI_TOKEN=...
GD_METAAPI_ACCOUNT_ID=...
```

الكود يرفض الإقلاع إذا اختلف `provider` عن `feed` — التنفيذ وقراءة الأسعار يجب أن يكونا من نفس الوسيط.

#### 4) أصول الارتباط
معظم وسطاء الفوركس لا يوفّرون DXY أو US10Y. اضبط ما يوفّره وسيطك في `config/symbols.yaml` تحت `metaapi_correlation` (مثلاً `SPX500: "US500"`). ما لا يتوفر يُسقط تلقائياً وتُحيَّد البوابة بدل أن تمنع التداول.

#### 5) التكلفة
MetaApi لها فترة مجانية ثم اشتراك شهري يبدأ عادة حول 20$ لحساب واحد. راجع تسعيرهم الحالي.

## 10) حل المشاكل

| العَرَض | السبب والحل |
|---|---|
| `❌ التخزين غير قابل للكتابة` | القرص غير مركّب على `/data` أو الصلاحيات — أعد إنشاء الـ Volume بمسار `/data` بالضبط |
| `فشل الطلب ... 429` | تجاوزت حصة المزوّد — ارفع `SCAN_INTERVAL_SECONDS` أو انتقل إلى Twelve Data بمفتاح |
| `عدد الشموع أقل من الحد الأدنى` | السوق مغلق (عطلة نهاية الأسبوع) أو الرمز خاطئ — تحقق من `GD_BOT__LIVE_SYMBOL` |
| لا تصل إشعارات Telegram | تحقق من التوكن والـ chat_id، وأنك أرسلت رسالة للبوت أولاً |
| البوت يعيد التشغيل باستمرار | راجع السجلات؛ غالباً خطأ إعدادات — `railway run python -m src.main doctor` |
| لا إشارات منذ أيام | طبيعي. تحقق من `/status`؛ إن كان `last_scan` يتحدث فالبوت بخير |

## 11) إيقاف طارئ

```bash
railway run python -m src.main kill --trigger "إيقاف يدوي" --level pause
```
أو ببساطة: **Settings → Remove Service** / إيقاف الخدمة من اللوحة.

للاستئناف بعد إيقاف اضطراري:
```bash
railway run python -m src.main kill --reset
```
